I Built a Simple Event Check-In System

Sometimes a project starts with a very simple question: “Could I make this process a little easier?” That was the question behind this project. I wanted to explore whether a simple digital workflow could make event registration and check-in easier.

The Idea

I’ve been around different events where checking people in can involve searching through lists, confirming names, and manually keeping track of who has arrived. It got me thinking about whether a simple digital workflow could make the process a little easier.

I didn’t set out to build a complicated event-management system. I just wanted to experiment.

I decided to see what I could build using tools that I already had access to: Google Forms and Google Sheets. The idea was to create a workflow that could move from registration to check-in and eventually turn the collected information into something useful.

Registration Form → Form Responses → Guest Check-In → Attendance Data → Dashboard

For the prototype, I used synthetic/test data rather than real attendee information.

Starting With Registration

I started with a simple Google Form to collect attendee information. Once someone submits the form, the responses are automatically captured in Google Sheets. This gave me a source of registration data that I could then use for the check-in process.

One thing I wanted to avoid was having the person doing the check-in work directly inside the raw responses. So I created a separate Guest Check-In workspace.

Building the Check-In Workflow

The check-in sheet contains the information needed to identify an attendee and record their arrival. At the moment, it tracks:

  • Full Name
  • Email
  • Check-In Status
  • Check-In Time

I also added a dropdown for the check-in status:

  • Checked_In
  • Not Checked In

When someone arrives, their status can be updated and their check-in time recorded.

It’s a relatively simple setup, but building it made me think more about the person who would actually be using the system. A volunteer checking in guests doesn’t need to see every piece of information collected during registration. They need to be able to find the person, confirm who they are, and check them in quickly.

That changed how I started thinking about the project.

From Check-In Data to Insights

Once I had the check-in information, I realized there was another opportunity. The same data could be used to understand what happened during the event.

So I created an attendance dashboard showing things such as:

  • Total registered
  • Total attended
  • Did not attend
  • Attendance rate
  • Attendance breakdown
  • Arrival progression

This was probably one of the parts I enjoyed most. The data was no longer just a list of names and statuses. It was beginning to tell a story about attendance.

It also reminded me why I enjoy working with data. Sometimes the value isn’t in collecting more data. It’s in making the data you already have easier to understand and use.

Then I Got Stuck

Of course, the project didn’t go exactly as planned. One feature I wanted was a simple search function. Ideally, a volunteer should be able to type someone’s name or email, find the attendee quickly, and update their check-in status.

I tried to work out how to implement this in Google Sheets, but I couldn’t get the search functionality working the way I wanted. And instead of pretending the project was finished, I decided to ask for help.

I shared the project and asked people who have worked with Google Sheets for suggestions. That became an important part of the project for me.

What This Project Taught Me

This project wasn’t really about creating a sophisticated technical system. It was about taking something I had observed, asking whether there was a better way, and actually trying to build it. A few things stood out to me.

Start with the user

It’s easy to think about what features a system should have. But thinking about who is actually going to use it changes the way you build. For this project, that meant keeping the check-in workspace focused and separating it from the raw registration data.

Simple tools can still solve real problems

I didn’t need a complicated application or a large technology stack to experiment with the idea. Google Forms and Google Sheets were enough to build a working prototype and explore the workflow.

Getting stuck is part of building

The search functionality is still unfinished. And that’s okay.

I’ve realized that building something doesn’t mean knowing everything beforehand. Sometimes you try something, get stuck, ask for help, test another approach, and keep moving.

What’s Next?

The biggest improvement I’m currently working on is the attendee search functionality. I want the check-in process to eventually look something like:

Search → Find attendee → Confirm → Check in

I’m also interested in improving the volunteer-facing interface and making the workflow faster and easier to use during a busy event. For now, though, I’m happy with what this small experiment has taught me.

Final Thoughts

This started with a simple question:

“Could I make event check-in a little easier?”

I don’t have a finished answer yet. But I now have a working prototype, a better understanding of the problem, and a list of things I want to improve.

And maybe that’s one of the things I enjoy most about building projects like this.

You don’t always have to start with a perfect idea or know exactly where you’re going.
